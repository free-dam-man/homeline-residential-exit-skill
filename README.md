# 🏠 家宽出口节点 Skill：让你的 AI 帮你在自己的 VPS 上搭一条「住宅 IP」线路

> 机房 IP 太"假"？把这个仓库丢给你的 AI，它会一步一步问你要哪个国家，然后在你自己的 VPS 上搭出一条**出口是真实运营商宽带 IP** 的 VLESS+Reality 线路，最后给你一个链接和二维码，扫码就能用。

## 这是什么

一份给 AI 用的部署说明书（Skill）。思路：

```text
你的手机/电脑 → 你 VPS 上独立的 Xray（VLESS+Reality，一个国家一个端口）
  → 本机 SOCKS5（只绑 127.0.0.1）→ 网关容器里的 OpenVPN
  → VPN Gate 公开的住宅节点 → 互联网（出口 = 住宅宽带 IP）
```

全部用免费的东西：VPN Gate 公开节点 + 开源 Xray + Docker。只需要你有一台 VPS（512MB 内存也能跑）。

## 实测状态（如实）

2026-10-21 在一台 512MB Debian 13 VPS 上，**只照本仓库从零重搭了一遍**（见 SKILL.md 第 2D 节）：

| 国家 | 状态 | 说明 |
|---|---|---|
| 🇰🇷 KR | ✅ 跑通 | 出口为韩国大型运营商宽带，非机房标记 |
| 🇯🇵 JP | ✅ 跑通（⚠️ 非真家宽） | 排名靠前的 JP 节点大多在 SoftEther 网段（AS36599），不是家庭宽带；新版脚本默认排除，需你同意才用 |
| 🇺🇸 US | ✅ 跑通 | 美国地区运营商，非机房标记，是否家宽待确认；可用节点很少 |
| 🇬🇧 UK | ❌ 未建成 | 测试时 VPN Gate 上没有英国节点 |

- 服务器端探测 + 外部真实 Xray 客户端都已验证出口国家；kill switch 实测不漏 VPS 本机 IP。**手机端测试待补**，欢迎反馈。
- 住宅节点会掉线、IP 会变。网关每分钟测一次真实流量，断流自动重启，链接不变。
- **定时巡检换节点是可选的**（`templates/heal.sh.example`，间隔自定）；不装也能用，节点彻底死了再手动重扫即可。

技术总结见 [`docs/TECH-SUMMARY.md`](docs/TECH-SUMMARY.md)。

## 怎么用（交给你的 AI）

1. 准备一台能装 Docker 的 Linux VPS，以及能改防火墙/安全组的权限。
2. 把本仓库（尤其是 `SKILL.md` 和 `templates/`）交给你的 AI 助手，说："按这个 Skill 帮我部署一条家宽线路"。
3. AI 会**向导式**一步步问你：要哪个国家、用哪个端口……你自己选。
4. AI 部署后必须**实测出口**（国家、运营商、是否机房标记），测出来是什么就如实告诉你，不会夸大。
5. 拿到 `vless://` 链接或二维码，导入 Shadowrocket / Clash / sing-box / v2rayN 即可。

### 通用启动口令（复制整段发给你的 AI）

```
请按这个公开仓库的 SKILL.md，在我的 VPS 上搭一条家宽（住宅 IP）出口线路，最后给我能导入客户端的节点：
https://github.com/free-dam-man/homeline-residential-exit-skill

规则：
1. 先完整读 SKILL.md 和 docs/TECH-SUMMARY.md，按主路线一步步做，templates/ 里的模板能用就直接用。
2. 只用免费方案，不开任何付费服务，不替我注册账号。
3. 动手前先问我：VPS 怎么连（地址、SSH 方式）、要哪个国家的出口（可多选，一国一条线路）、用什么客户端。一次只问一个问题。
4. 先盘点再动手：查清系统版本、内存、已有的端口、容器、服务和防火墙规则，汇报给我。机器上原有的任何东西都不许改、不许停、不许删。新线路只用确认空闲的端口、新目录、新容器名、新服务名，冲突了就改新线路。防火墙只加规则不删。内存小的机器先告诉我风险。
5. 必须带 kill switch，隧道断了不能从 VPS 自己的 IP 漏出去。网关每分钟测一次真实流量，断流自动重启。搭好后亲手验证一次断线不泄漏、能自动恢复。
6. 自己验证出口：查出口 IP 的国家、城市、运营商/ASN、是否机房 IP，再用真实客户端从外部连一次。结果如实报告，国家不对、是机房或 VPN 运营商网段、这个国家暂时没节点，都直接说，让我决定。
7. 定时巡检换节点是可选的，先问我要不要。
8. 最后给我：每条线路的链接和二维码、出口实测结果（标明测量时间）、遇到的坑和解决办法。凭证只发给我，不写进任何公开的地方。
```

> ⚠️ AI 不应改动你 VPS 上已有的服务和端口。如果你已有别的代理面板，部署前先让它确认端口不冲突。

更多细节、踩坑记录见 [`docs/DETAILS.md`](docs/DETAILS.md) 和 [`SKILL.md`](SKILL.md)，上游来源审计见 [`templates/SOURCES.md`](templates/SOURCES.md)。
